# DIALECT — what the H2 provider is verified against

Every claim below was checked by running SQL, not by reading prose. The reference side is the
pinned H2 jar (`h2-2.5.259-SNAPSHOT.jar`, commit `27c51709fef687bc064f23c8dd495b566c69bb93`)
run on the JVM; the port side is the H2Sharp ADO.NET layer.

Keep this file in step with the probes. A row that stops being true is worse than no row.

## Consequences for this provider

**Scaffolding is blocked on the engine, not on the provider.** `H2DatabaseModelFactory` is written
against `INFORMATION_SCHEMA`, verified above, and refuses with a message naming the missing engine
feature rather than returning an empty model. An empty model would be indistinguishable from an
empty database, and every migration generated from it would try to recreate existing tables.

**Value generation must be sequence-based, not RETURNING-based.** The reference engine has no
`INSERT … RETURNING`; it has `NEXT VALUE FOR`. The Npgsql model of "insert, then read back the key"
transfers as: insert with the value drawn from a sequence, or insert and read
`CURRENT VALUE FOR`. `IDENTITY` is the other option and the reference supports it — the port does
not yet.

**Identifier folding is upper case**, so the provider quotes every identifier it emits and the
default name translator folds to upper case, which is both H2's rule and the spelling a hand-written
H2 client would use.

**`Skip`/`Take` will work.** EF Core emits `LIMIT`/`OFFSET`, and the reference accepts both that and
the `FETCH` form. H2Sharp already executes `LIMIT`/`OFFSET`; this is one of the few places where the
provider is ahead of the port rather than behind it.

## Known gaps in the scaffolded model

* **Index columns live in a separate table.** `INFORMATION_SCHEMA.INDEXES` has no `COLUMN_NAME`;
  `INFORMATION_SCHEMA.INDEX_COLUMNS` is the one that has them. An earlier probe of mine read only the
  former and concluded the columns were unrecoverable — that conclusion was wrong, and acting on it would
  have produced scaffolding that silently omitted index columns.
* **`ON UPDATE` referential action is dropped.** EF Core's `DatabaseForeignKey` has no member for it,
  so there is nowhere to carry it. `ON DELETE` is carried.
* **Precision, scale and length live in `DECLARED_DATA_TYPE`,** which is the type as written in the
  DDL. EF Core's scaffolding model has no separate members for them either, so the declared form is
  what `StoreType` holds.

## Connection strings

`H2Connection` takes a JDBC-style URL (`jdbc:h2:mem:probe`), not `Data Source=…`. A connection string
handed to `UseH2` must go through `H2ConnectionStringBuilder.ToH2ConnectionString()` first; passing
`Data Source=…` straight to `H2Connection` fails with a syntax error inside the URL parser.

`SELECT *` is likewise rejected by the current parameter rewriter (`[*]url`). Enumerate columns.
