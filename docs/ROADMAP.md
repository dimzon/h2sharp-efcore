# Roadmap — H2Sharp.EntityFrameworkCore

## Готово

* Форк EFCore.PG v9.0.5: пространство имён, сборка, пакет и точка входа переименованы
  (`UseH2`, `AddH2`, `H2:`-аннотации). `UPSTREAM.md` фиксирует точку отсчёта.
* ADO-слой заменён на `H2Sharp.Data`: `H2Connection`, `H2Command`, `H2Parameter`,
  `H2DataReader`, `H2Transaction`, `H2ProviderFactory`, `H2ConnectionStringBuilder`.
* Удалена поверхность PostgreSQL, которой у H2 нет: ranges и multiranges, inet/cidr/macaddr,
  tsvector/tsquery и полнотекстовый поиск, hstore, ltree, reg\*, tid, pg_lsn, money, varbit,
  семь геометрических типов, unsigned-типы. Перечисление — в истории коммитов.
* Таблица store-типов — H2-овая; типы пишутся теми написаниями, которые читает парсер
  движка (`VARCHAR`, `CLOB`, `VARBINARY`, `BLOB`, `TIMESTAMP`, `TIME`, `JSON`).
* `SerialColumn` трактуется как identity: в H2 нет псевдотипа `serial`, единственный
  авто-генерируемый столбец — `GENERATED BY DEFAULT AS IDENTITY`.
* `H2DatabaseCreator` управляет схемой (`INFORMATION_SCHEMA.SCHEMATA`, `CREATE SCHEMA`,
  `DROP ALL OBJECTS` + `DROP SCHEMA CASCADE`) вместо серверной модели PostgreSQL.
* `H2DatabaseModelFactory` читает `INFORMATION_SCHEMA` вместо `pg_catalog`.
* Коды ошибок — H2-овые, взятые из движка: `DuplicateKey1` (23505),
  `TableOrViewAlreadyExists1` (42101), `LockTimeout1` (50200), `Deadlock1` (40001).
* Идентификаторы кавычатся всегда: H2 сворачивает некавыченное в UPPER, и `title` доехал бы
  как `TITLE` — модель перестала бы описывать свою же схему.
* Строка подключения переводится в H2-URL; всё, что не имя базы, уходит в хвост URL как
  настройки H2 (`MODE`, `DATABASE_TO_LOWER`, `DB_CLOSE_DELAY`).

Проверено: сгенерированный DDL принимает эталонная H2 2.5 (прогон против пиннованного jar).

## Дальнейшие планы

### AST-вход вместо текста SQL

Наблюдение, из которого это растёт: **разрыв между движком и его парсером**. Объектная модель
identity-колонок уже есть (`Tables/Column.cs` — `IsIdentity()`, `isGeneratedAlways`), объект
последовательности тоже (`Schemas/Sequence.cs`), ограничения — тоже. Парсер просто не умеет
прочитать соответствующий синтаксис. Отсутствует не реализация, а вход.

Форма, которую считаем правильной — **второй вход в одну реализацию**, а не второй движок:

* сегодня `Parser.ParseOneStatement()` (private) строит `Prepared`/`Command` из `Statement`;
* этот кусок выносится в публичный вход — `Session.PrepareCommand(Statement)` либо отдельный
  `StatementExecutor`;
* парсер становится клиентом этого входа.

Иначе получатся две реализации DDL, которые разойдутся, — а правила проекта это запрещают
(«свой обход, где у эталон свой»).

Что нужно доработать в AST-записях:

| запись | сейчас | нужно |
|---|---|---|
| `ColumnDefinition` | Name, Type, NotNull, PrimaryKey, ConstraintName, PrimaryKeyHash | `IsIdentity`, `IsGeneratedAlways` |
| `TableConstraintDefinition` | Name, IfNotExists, Columns, Hash | тип ограничения, referenced table/columns, on delete/update |
| — | нет | записи `CREATE SEQUENCE` / `ALTER SEQUENCE` |

Ограничение, которое надо помнить: **провайдер EF Core не может передать AST в EF Core.**
EF Core Relational текстовая система от `RelationalQuerySqlGenerator` до
`RelationalCommand.CommandText`. Обойти текст можно только там, где DDL формирует сам провайдер:

| путь | минуя текст | почему |
|---|---|---|
| DDL (миграции, `EnsureCreated`) | да | провайдер сам строит команду |
| SELECT / INSERT / UPDATE | нет | конвейер EF текстовый; обход — это переписать конвейер EF |

То есть AST-путь снимает те блокеры, которые сейчас стопорят миграции: identity, sequence и
foreign key в DDL.

Выигрыш в том, что код против типизированного API ловится компилятором, а не парсером:

```csharp
new CreateTableStatement
{
    Name = "Blogs",
    Columns =
    {
        new ColumnDefinition("Id", "integer", NotNull: true, IsIdentity: true),
        new ColumnDefinition("Title", "varchar"),
    },
    Constraints = { new TableConstraintDefinition("PK_Blogs", Columns: ["Id"]) },
}
```

### Разделение работы

* **Команда над движком**: публичный AST-вход, расширение записей, тесты, сверяющие AST-путь
  с парсером на JVM-оракуле.
* **Здесь**: ADO-слой (`H2Command`/`H2Connection` получают путь «выполнить Statement») и
  провайдер (DDL-генерация через AST вместо текста).

### Пробелы движка, на которые опирается провайдер

Провайдер генерирует H2-корректный SQL; пока движок не догонит, часть DDL не выполнится.
Каждый пункт — в `docs/DIVERGENCES.md` с пометкой «пробел движка», а не обходится.

* `ALTER TABLE` читает `ADD`/`DROP CONSTRAINT`, но не `RENAME TO`, `ALTER COLUMN`,
  `DROP COLUMN`, `DROP DEFAULT` и не `ADD CONSTRAINT … UNIQUE` (пробелы 7 и 21);
* интервальные типы (`INTERVAL DAY TO SECOND`) не создаются (пробел 4);
* `TIME WITH TIME ZONE` не создаётся как тип столбца;
* в каталоге у колонки пуст `collation` (пробел 8);
* параметр-число в `TIMESTAMPADD` (пробел 16) и `= ANY (массив-параметр)` (пробел 10)
  движок не читает;
* `SPATIAL`/`HASH`-индексы (пробел 19) и `INCLUDE` у уникального индекса (пробел 20) не
  читаются.

Портированы и потому пробелами не являются: identity-колонки и `FINAL TABLE` (значение
identity возвращается к вызывающему), `CREATE SEQUENCE`/`NEXT VALUE FOR`, `FOREIGN KEY` в
`CREATE TABLE`, `INFORMATION_SCHEMA`, `CREATE SCHEMA`, `JOIN`, производные таблицы,
`EXISTS`, `IN` с подзапросом, `INTERSECT`/`EXCEPT`, `WITHIN GROUP`/`FILTER`, `SAVEPOINT`,
`UNNEST`, тип `ARRAY` и row-value. Актуальный перечень — в `docs/DIVERGENCES.md`.
